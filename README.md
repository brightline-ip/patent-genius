# Patent Genius

**Public preview 0.1.0**: structural checks only; the parser has been checked only against section headings; no model interpretation. Collection from the USPTO and the Hub gateway were tested against a stand-in for the Hub, never against the live service.

Patent Genius is an offline-first toolkit for patent-prosecution analysis, written for IP practitioners and the people
who build tools for them. It runs on your computer, uses only the Python standard library for its core, and never
judges whether a claim is legally sufficient. It does these things:

1. **Evidence and coverage checks.** Import a manifest of source documents (each pinned by SHA-256), retrieve passages
   by structure (document type, technology, CPC, matter namespace), and audit a draft against a coverage plan: are the
   cited evidence IDs real, do quotations match the source, are required sections present, is anything still marked
   unknown. The audit proves *typed record presence and hash integrity only*; it always reports
   `semantic_support_verified: false` and `legal_sufficiency_verified: false`.
2. **Office-action parsing.** A rule-based parser reads the text of a USPTO office action and extracts rejections
   (statute, claims, cited references), objections, restriction, double patenting, finality, AIA status and header facts
   (art unit, examiner, mail date), each with the evidence for it. Cited references are normalised to document numbers
   when they have one; a bare surname is kept as written and is never used for matching. It then outlines the issues a
   response would need to address. It chooses no strategy.
3. **Your own scope and your own data.** One file, `scope.json`, says which technology fields (a name you choose plus the
   CPC symbols that define it), which filing dates and which document types you work on. Tools to build, freeze and sample
   sets of USPTO applications ("frames"), to turn public file-wrapper documents into compact, hash-linked Markdown, and to
   build a local SQLite database from what you collected. Harvesting live data needs the optional
   [Patent Research Hub](docs/HUB.md) (0.2.0 or later), which holds your USPTO key.
4. **Collecting office-action rejection rows** for the applications in your own frames (`pg_cli.py collect`, resumable,
   paced by the Hub, with a dry-run estimate first): see [docs/COLLECTING.md](docs/COLLECTING.md) for what the USPTO requires of you.
5. **Descriptive statistics.** Rejection rates, allowance rates with and without a prosecution event, examiner and
   art-unit tables, each tied to the frames and data you built, with the denominators and what was not collected.
6. **Similar office actions and a response material pack.** A published, deterministic similarity over your database
   ([docs/SIMILAR.md](docs/SIMILAR.md)), and a pack of typed facts, counts and pointers for one action that contains
   **no tool-authored argument text** ([docs/PACK.md](docs/PACK.md)). Neither drafts or advises.

> **Not legal advice.** Every generated document or report is headed *"DRAFT — generated by Patent Genius; not legal
> advice; requires review by a registered practitioner"*. See [DISCLAIMER.md](DISCLAIMER.md).

## Requirements

| | |
|---|---|
| OS | Developed and tested on Windows 11. The code is portable Python/Node and should run on Linux and macOS, but that has not been verified. |
| Python | 3.10 or newer (tested with 3.14). Standard library only: `requirements.txt` lists nothing mandatory. |
| Node.js | 24.13 or newer (tested with 24.13), only for the `frame_*.mjs` harvest and `acquire_*.mjs` document-download scripts. `pg collect` (office-action rows) is Python and needs only the Hub. No npm packages. |
| Hub | Patent Research Hub **0.2.0 or later** for any collection (its `gateway` command); not needed for anything offline. |
| Optional | PyMuPDF and the Tesseract program for OCR of scanned PDFs (`ocr_run.py`); the Patent Research Hub (0.2.0 or later) for collecting USPTO data. |

## Install

**Windows (per user, no administrator rights):** extract the zip, then double-click `Setup.cmd`. It copies the program to
`%LOCALAPPDATA%\Brightline\PatentGenius`, creates a separate data folder `%LOCALAPPDATA%\Brightline\PatentGenius-Data` that only
your account can read (with an example `scope.json`), writes `PatentGenius.cmd` (the command line) and `MCP-setup.json` /
`MCP-setup.codex.toml` (paths only: Patent Genius has no keys), and adds Start Menu shortcuts (Check, Data folder, Documentation,
Repair, Uninstall). It needs Python 3.10 or newer; if it is missing, Setup offers it through winget and installs nothing unless you
say yes. Node.js 24.13 or newer (only for the `*.mjs` harvest and download scripts) and PyMuPDF (only for OCR, in a private `.venv`) are offered the same way.
If the Patent Research Hub 0.2.0 or later is found, its `Hub.cmd` is recorded as `PG_HUB_CMD`; a missing or older Hub is only a
warning. `Setup.cmd -DryRun` shows what it would do without changing anything. Setup never edits an AI assistant's configuration.

**From a clone (any system):**

```
git clone <this repository> patent-genius
cd patent-genius
python pg_cli.py doctor
```

There is nothing to `pip install`. `doctor` checks Python, Node, your data folder, the Hub and Tesseract, and makes no
network call (it asks the Hub only for its version, with `gateway --limits`).

## Your data folder

Everything you create lives in ONE folder, kept apart from the program files:

- `--data-dir <folder>` on a command, else the environment variable `PG_TOOL_DATA_DIR`, else
  `%LOCALAPPDATA%\Brightline\PatentGenius-Data` on Windows (`~/.local/share/brightline/patent-genius-data` elsewhere).
- It holds `scope.json`, `inputs/` (office-action text files you want read), `corpus/` (frames, events, normalized
  documents, `pg.db`), `public-originals/` and `locks/`.
- Writing inside the install folder is refused, so your data never mixes with the program or a source checkout.
- **Input folders.** `PG_TOOL_INPUT_ROOTS` (default `examples/` and `<data folder>/inputs`) are the folders from which a `file_path` may be read. **Any `.txt` or `.md`
  file inside one of them is readable by whatever asks** (your AI assistant, through the MCP server): keep secrets, notes and credentials out of those folders.
  A path with a `:` beyond the drive letter (an NTFS alternate data stream such as `file.txt:name`) is refused everywhere a path is read or written.
- **Smallest group (`min_n`).** Shares, rates and counts are not shown for fewer cases than `min_n`, which is never below 5: a smaller value is refused
  (`invalid_input` over MCP, an error on the command line), not silently raised.

## Quick start (about one minute, no network)

The repository ships an invented sample: `examples/manifest.json` (an invented disclosure) and
`examples/sample/office-action.txt` (an invented final office action for an invented application).

```
# 1. Evidence checks on the invented disclosure
python patent_genius.py import examples/manifest.json --output snapshot.json
python patent_genius.py retrieve examples/manifest.json --namespace client:demo --technology agrotech
python patent_genius.py audit examples/manifest.json examples/claim-coverage.json examples/draft.md
#    -> status MECHANICAL_CHECKS_ONLY (exit 0); examples/coverage.json deliberately returns REVIEW_REQUIRED (exit 1)

# 2. Read the invented office action (a rule-based outline, not advice; prints to the screen, writes nothing)
python pg_cli.py assess examples/sample/office-action.txt
python pg_cli.py assess examples/sample/office-action.txt --markdown

# 3. Your scope, then an (empty) database
python pg_cli.py scope init            # writes an editable example scope.json into your data folder
python pg_cli.py scope validate
python pg_cli.py db build              # every input is optional; on an empty folder it builds an empty database
python pg_cli.py db report coverage    # what the database holds and what was "not collected"

# 4. Collect, then ask (needs the Hub and your own USPTO key; the plan makes no request)
python pg_cli.py collect plan          # applications, requests, time and disk, from the Hub's own limits
python pg_cli.py collect run --yes     # resumable; stop and start it as you like
python pg_cli.py db build
python pg_cli.py similar my-action.txt --application 17000001
python pg_cli.py pack my-action.txt --out my-pack.json
python pg_cli.py shell office-action-response --from-pack my-pack.json

# 5. See all tools
python pg_tool_mcp.py --cli list
```

`assess --out <file>` writes the result to the path you name; the result then says `persisted_by_tool: true`. Without
`--out` nothing is written, anywhere. PDFs must be converted to text first.

Run the tests (offline, no sibling repositories needed):

```
python -B -m unittest discover -s tests
```

## Scope

`scope.json` is the only place that fixes technology fields, CPC symbols, filing dates and document types; the program
has none built in. See [`examples/scope.example.json`](examples/scope.example.json) (invented fields `agri` and
`soil_sensing`) and [`schemas/scope.schema.json`](schemas/scope.schema.json).

- `fields[]`: `{name, seeds, historical_prefixes}`. A name is lower case letters, digits and underscores, starts with a
  letter, and is not a Windows device name (`con`, `nul`, `com1` ...).
- `filing`: `{from, to_exclusive, window_days}`. Frames are built by **filing** date, any year from 1976.
- `publication_years`: a filter on reports only; it never changes how frames are built.
- `documents`: `preset` is `none` (the default, nothing is downloaded), `office-actions`, `prosecution`, `procedural`, or
  `custom` with `codes`.
- `limits`, `sample`, `data_types`: caps and intent; nothing is collected unless you run a collection command.

## The tools

`python pg_tool_mcp.py --cli <tool> --input '<json>'` and the MCP server expose the same eleven tools (contract 1.1.0); their input and
output schemas are in [`pg_tool/contract.json`](pg_tool/contract.json). Every result is an envelope with `status`,
`data`, `provenance`, `caveats`, `warnings`, a `boundary` block (what was persisted, whether a model or live call was
used) and a fixed disclaimer.

| Tool | What it does | Needs data you build |
|---|---|---|
| `pg_status` | What local data and scope are present; which data, database and Hub command are present (starts nothing) | no |
| `pg_assess_office_action` | Rule-based extraction + issue outline from office-action text; `partial` if the result does not fit its schema | no |
| `pg_template` | One of the eight structural document shells in `templates/` | no |
| `pg_report` | Markdown report from the above | no |
| `pg_search`, `pg_trends`, `pg_post_grant`, `pg_corpus` | Search/aggregate/read your own frames, rejection data, PTAB / Federal Circuit data and normalized documents | yes (see [docs/FRAMES.md](docs/FRAMES.md), [docs/RETENTION.md](docs/RETENTION.md)) |
| `pg_similar_office_actions` | Rank the office actions in your database by a published weighted similarity; counts with intervals, one case per family, open cases apart ([docs/SIMILAR.md](docs/SIMILAR.md)) | yes (database) |
| `pg_response_pack` | Typed facts, issues, authority pointers, counts and a fact-filled shell for one action; no tool-authored argument text; built in memory ([docs/PACK.md](docs/PACK.md)) | no (richer with a database) |
| `pg_db_report` | A named report from the database (overview, rejection rates, examiners, art units, coverage); exact examiner match only; small groups left out | yes (database) |

Without that data these tools return `not_found` or `partial` with a warning; nothing is invented. This build collects
office-action rejection rows (`pg_cli.py collect`) but has no collector for PTAB or Federal Circuit data: the tools read
such files if you supply them in the layout described in [docs/FRAMES.md](docs/FRAMES.md). **Live provider search: planned.** In 0.1.0 `pg_search` reads your own frames only (`local-frames`) and no tool makes a provider call; data is collected from the command line (`pg_cli.py collect`, and the `acquire_*` and `frame_*` scripts), which reach providers only through the Hub's gateway command.

### Document shells (what generates text)

`templates/` holds eight *structural* shells: `application`, `client-update`, `interview-notes`, `invention-intake`,
`oa-issue-inventory`, `office-action-response`, `restriction-election`, `summary`. Each is a list of section headings
with bracketed prompts ("mark unknowns explicitly") and carries the DRAFT header. They contain no argument text.
`pg_template` returns them; `pg_report` and `pg_assess_office_action` produce Markdown/JSON drafts that also carry the
header. The program loads no other templates, from any folder.

## MCP client registration

The server speaks MCP over stdio (newline-delimited JSON-RPC 2.0) and needs no packages. Add it to your client, for
example (use your own absolute paths):

```json
{
  "mcpServers": {
    "patent-genius": {
      "command": "python",
      "args": ["C:/path/to/patent-genius/pg_tool_mcp.py"],
      "env": { "PG_TOOL_INPUT_ROOTS": "C:/path/to/your/office-actions", "PG_TOOL_DATA_DIR": "C:/path/to/your/data-folder" }
    }
  }
}
```

Tool descriptions repeat the disclaimer. Everything the server returns is deterministic; no model is called.
[`skills/patent-genius/SKILL.md`](skills/patent-genius/SKILL.md) is a ready-made agent skill describing how to use it.

## Configuration

Patent Genius reads environment variables only (see [`.env.example`](.env.example)); it does not load `.env` files.

| Variable | Purpose | Default |
|---|---|---|
| `PG_TOOL_DATA_DIR` | The one data folder (`scope.json`, `corpus/`, `public-originals/`, `locks/`, `pg.db`); a folder inside the install folder is refused | per-user folder (see above) |
| `PG_TOOL_INPUT_ROOTS` | Folders (absolute, `os.pathsep`-separated) from which `file_path` may be read | `examples/`, `<data folder>/inputs` |
| `PG_HUB_CMD` | Full path of the Hub's `Hub.cmd` (the gateway command Patent Genius starts for every provider call) | unset: looked for in `PG_HUB_ROOT`, then the Hub installer's default folder |
| `PG_HUB_ROOT` (alias `PG_TOOL_HUB_ROOT`) | Patent Research Hub install directory (`Hub.cmd` inside it) | unset: nothing that needs the Hub works; the offline tools do |
| `PG_HUB_DISCOVER` | `0` switches off the look-up in the Hub installer's default folder | on |
| `PG_PYTHON` | Python executable for scripts that start Python | `python3` (`python` on Windows) |
| `PG_BUDGET_FRAMES` | Regex of frame ids that must reserve requests in a ledger (`PG_BUDGET_LEDGER`; see docs/FRAMES.md) | off |
| `PG_TESSERACT` | Tesseract executable for `ocr_run.py` | `tesseract` on PATH |

## Security model

- Local-only, stdio-only: no listener, no telemetry, no accounts.
- `file_path` reads are confined to `.txt`/`.md` files under allowed roots; paths are resolved (symlinks included) and
  re-checked, relative or filesystem-root entries are ignored, reads are size-bounded. Tests: `tests/test_input_roots.py`.
- Caller-supplied office-action text is processed in memory. Nothing extracted from it (header facts, application number,
  art unit, references) is written anywhere, and no provider or network query is made from it; the only thing done with it is
  local read-only database queries (for example leaving that application out of the similar results): `tests/test_caller_text.py`.
- Text taken from documents (citation strings, restriction descriptions, excerpts, quotes) is untrusted data, not instructions:
  results carry a fixed caveat saying so. The strings Patent Genius copies into its own fields (citation strings and the reference ids built from them,
  restriction descriptions, excerpts, header values, plan text, provider descriptions in the coverage report, pack quotes) have control, bidirectional
  and invisible characters replaced by spaces and are capped. `pg_corpus` returns the text of a local document as it is (raw), with the caveat only;
  `pg_search` and `pg_post_grant` return provider text with the caveat only. Cleaning lowers the chance of hidden formatting; it does not make text safe to obey.
- Collection and the frame harvest scripts reach providers only through the Hub's gateway command, started as a short-lived child
  per call: Patent Genius never reads `keys.env` and the Python tool service never holds a key. Only application numbers from your
  own frames are sent. The pack is built in memory; the command line writes only to a path you name.
- No tool makes a provider call (live provider search is planned). The downloaders and the harvest scripts also go only through the Hub gateway command, so no
  Patent Genius process holds a key and nothing imports a Hub module (a test greps for it).
- Source text is inert evidence, never executed. XML with DTDs/entities is refused; archives are never extracted to disk.

Report vulnerabilities as described in [SECURITY.md](SECURITY.md).

## Limitations

- Public preview. The parser has been checked only for agreement with section headings; no practitioner-verified sample
  exists. Treat every extracted finding as unverified. Header facts are read from the text and are unverified.
- The audit checks structure, hashes and span arithmetic. It cannot tell you that a claim is supported or sufficient.
- Statistics are only as good as the frames and data you build; they are descriptive, not predictive. The coverage
  report lists what was not collected and which applications were skipped.
- Tested on Windows 11 with Python 3.14 and 3.11 and Node 24 only. The installer was tested under Windows PowerShell 5.1 into scratch folders on the developer's machine; a clean-machine installation, and the winget paths (never started by the tests), have not been verified.
- The statute-specific evidence templates of the project this was derived from are not included. The response pack and the shells contain no argument text.
- Office-action rejection collection was built against the documented contract and a small read-only probe of the service; the Hub's direct transport,
  a 429 and the citations API have not been exercised live, the USPTO calls this API **Legacy**, and rate limits can change. Statutes are read at statute
  level only (the provider has no 112 subsections). References come from parsing full-text actions you collected.
- `pg_tool/authorities.json` (section pointers) and the default similarity weights have **not been reviewed by a practitioner**.

## Uninstall

Windows: the Start Menu shortcut "Patent Genius - Uninstall" (or `installer\remove.ps1`). It stops this installation's own processes,
removes the program folder and the shortcuts, and says for each folder whether it was deleted or kept. Your data folder is **kept**
unless you choose to delete it: it keeps your scope, collected data and the database, and **`inputs\` (office actions you saved there)
and `packs\` (packs you wrote) remain** until you delete the folder yourself; they can hold client-confidential material. Python,
Node.js and the Hub stay installed. Remove the MCP entry from your client's configuration yourself.
From a clone, delete the folder; nothing is installed system-wide.
